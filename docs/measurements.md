# Замеры parser-core

Снято на Apple M1 Pro, 16 ГБ, macOS, `cargo build --release`, rustc 1.89. Одна демка: `samples/test_demo.dem` (de_mirage, 58 МБ, 56 705 тиков, 10 раундов, 10 игроков). Это короткий матч, полный на 24-30 раундов в 2.5-3 раза длиннее; оценки для него ниже посчитаны линейной экстраполяцией и помечены. Команда: `/usr/bin/time -l cargo run --release -p parser-core --example parse -- samples/test_demo.dem out.json`.

## Время

| Шаг | Время |
|---|---|
| Проход 1: события, ростер, раунды | 0,3 с |
| Проход 2: снимки игроков | 0,5 с |
| Проход 3: снаряды | 0,4 с |
| Сборка и статистика | 0,1 с |
| **Всего** | **1,3 с** (стабильно по трём запускам) |

Около 44 тыс. тиков в секунду. Время растёт линейно с длиной демки: поиск тиков в списке `wanted_ticks` проверен отдельно (список в 20 раз длиннее не изменил время), квадратичного роста нет.

Оценка (не измерена): полный матч в 170 тыс. тиков разбирается около 4 с на этой машине. iPad 7 (A10 Fusion) заметно слабее, порядок 4-6 раз медленнее, то есть 15-25 с. Нужно проверить на устройстве (этап 10).

## Память

| Показатель | Значение |
|---|---|
| Пиковый footprint (физическая память процесса) | около 100 МБ |
| Максимальный RSS | около 185 МБ |

Разница это страницы отображённого файла демки (58 МБ), которые система вытесняет при нехватке памяти. Три прохода идут по одному отображению файла. Память пропорциональна числу снимков и записей снарядов, а не размеру файла: оценка (не измерена) для полного матча 250-300 МБ footprint. Лимит приложения на iPad с 3 ГБ порядка 1,4-2 ГБ, запас есть, но это нужно подтвердить на устройстве.

## Размер JSON

| Вариант | Размер |
|---|---|
| Компактный JSON | 5,3 МБ |
| gzip | 0,84 МБ |

Разбивка по разделам (компактный JSON, 5,18 МБ):

| Раздел | Размер | Доля |
|---|---|---|
| `tracks` (снимки игроков) | 4,3 МБ | 85% |
| `grenades` (траектория на каждом тике) | 0,47 МБ | 9% |
| `bomb` | 0,18 МБ | 3% |
| `ticks` | 0,07 МБ | 1% |
| остальное (события, статистика, сводки) | меньше 0,02 МБ | менее 1% |

Внутри `tracks`: координаты `x`, `y`, `z` около 2,3 МБ, углы `yaw`, `pitch` около 1 МБ, `money` 0,54 МБ, `hp` 0,43 МБ, оружие и инвентарь менее 0,04 МБ.

Оценка (не измерена) для полного матча в 30 раундов: 15-16 МБ без сжатия, около 2,5 МБ в gzip. Это вдвое меньше оценки спецификации (30-40 МБ).

Если размер станет проблемой, самые дешёвые меры: `money` меняется редко, его можно хранить списком смен; положения кодировать разностями от предыдущего снимка.

## Что проверено тестами

`cargo test -p parser-core` (тесты на демке пропускаются без `samples/test_demo.dem`):

- длины всех массивов совпадают с `ticks`, hp в 0..100, углы в диапазоне, шаг снимков 4;
- совпадение числа гранат и областей с событиями демки, убийств и смертей между собой, итогов статистики с суммой по раундам;
- все индексы игроков и оружия в событиях, бомбе и гранатах указывают на существующие записи;
- побайтное совпадение с эталоном `samples/test_demo.expected.json.gz` и повторяемость вывода;
- плохой ввод (пустой, мусор, чужой формат, обрезанная демка, нет файла) даёт ошибку, а не падение.

## Не проверено

- Полный матч на 24-30 раундов, овертайм, демки других карт и режимов. Есть только одна короткая демка.
- Демки после обновлений игры: формат меняется, зависимость demoparser2 закреплена на коммите.
- Время и память на iPad.
