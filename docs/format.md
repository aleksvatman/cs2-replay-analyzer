# Формат JSON (schemaVersion 1)

Контракт между `parser-core`, сервером и приложением. Источник истины в коде: `parser-core/src/models.rs`. Любое несовместимое изменение формата повышает `schemaVersion`.

Сериализация: `parser_core::to_json` / `write_json` дают компактный JSON (без пробелов), ключи в `camelCase`, кортежи (`kills`, `damage`, `blinds`, `inventory`, `weapon`) это массивы. Эталон: `samples/test_demo.expected.json.gz`.

Статус: реализованы верхний уровень, `players`, раунды, снимки игроков с экономикой, события, бомба, гранаты и статистика (этапы 3-7a). Остальное ниже помечено «план» и пока не в коде.

## Верхний уровень

| Поле | Тип | Описание |
|---|---|---|
| `schemaVersion` | число | Версия формата, сейчас 1 |
| `map` | строка | Название карты, например `de_mirage` |
| `tickRate` | число | Тиков в секунду. Демка частоту не отдаёт: считается как тики / `game_time` по первому раунду, при сбое 64 |
| `players` | список | Игроки матча |
| `weapons` | список строк | Словарь названий оружия и предметов: в данных только индексы (порядок первого появления) |
| `rounds` | список | Раунды по порядку |
| `stats` | объект | Статистика по игрокам (план, этап 7a) |

## players

`{ index, steamId, name, finalTeam }`. `index` используется везде как ссылка на игрока. `finalTeam` это `"T"`, `"CT"` или `null`: сторона в конце матча. Стороны меняются на полувремени, поэтому команда в конкретном раунде хранится в раунде (`teams`, план, этап 4).

## rounds

Сейчас:

| Поле | Описание |
|---|---|
| `number` | Номер с 1, овертайм продолжает счёт |
| `startTick` | Тик начала раунда (`round_start`; для первого раунда не раньше `begin_new_match`) |
| `freezeEndTick` | Конец заморозки (`round_freeze_end`), `null`, если раунд кончился раньше (сдача) |
| `endTick` | Тик `round_end` |
| `winner` | `"T"`, `"CT"` или `null` |
| `reason` | Код причины из игры: 1 взрыв бомбы, 7 разминирование, 8 убиты все T, 9 убиты все CT, 18 сдача CT. Неизвестные коды передаются как есть |

Раунды собираются так: всё до `begin_new_match` (разминка, рестарты) отбрасывается; раунд существует, только если у него есть начало и конец, оборванный в конце раунд не попадает в результат.

Снимки (этап 4). Все массивы игрока имеют длину `ticks`; индекс `i` везде значит снимок `i`.

| Поле | Описание |
|---|---|
| `ticks` | Тики снимков: `startTick`, +4, +8, ... до `endTick` (заморозка включена) |
| `teams` | Сторона каждого игрока в этом раунде (`"T"`, `"CT"`, `null`), индекс = `players[].index` |
| `tracks` | Данные игроков, индекс = `players[].index` |

`tracks[p]`:

| Поле | Описание |
|---|---|
| `x`, `y`, `z` | Позиция, целые десятые игровой единицы. У мёртвого сохраняется последняя известная позиция |
| `yaw`, `pitch` | Целые десятые градуса: yaw -1800..1800, pitch -900..900 |
| `hp` | 0..100, `0` значит мёртв |
| `weapon` | Смены активного оружия: пары `[i, id оружия]` (первая запись на первом снимке с живым игроком) |
| `money` | Деньги на каждом снимке |
| `inventory` | Смены инвентаря: `[i, броня, флаги, [id предметов]]`. Флаги: бит 0 шлем, бит 1 набор сапёра. Запись на первом снимке и при каждом изменении |
| `spent` | Потрачено за закупку: `cash_spent_this_round` на последнем снимке до конца заморозки |

Для мёртвого игрока `weapon` и `inventory` не обновляются (остаётся состояние перед смертью). Игрок, которого нет в данных тика, считается мёртвым.

### events (этап 5)

Короткие списки-кортежи, первым всегда тик. Игрок это `players[].index`, `-1` значит «никто» (урон от мира, нет ассистента, неизвестный игрок). Раунд владеет событиями с тиками `[startTick, startTick следующего раунда)`, поэтому убийства после `round_end` остаются в своём раунде; у последнего раунда события после `endTick` отбрасываются (это завершение демки: игроки отключаются, «убийства миром»). Последнее убийство на тике `round_end` может быть не видно в `hp`, так как последний снимок не позже `endTick`.

Названия оружия в событиях это внутренние имена игры (`ak47`, `hegrenade`, `world`), они попадают в тот же словарь `weapons`, что и инвентарь (`AK-47`), но как отдельные записи.

| Список | Кортеж |
|---|---|
| `kills` | `[tick, killer, victim, assister, weapon, flags]`. Флаги: 1 хедшот, 2 через дым, 4 через стену, 8 без прицела, 16 убийца ослеплён, 32 помощь флешкой |
| `damage` | `[tick, attacker, victim, weapon, healthDmg, armorDmg, victimHpAfter]`. `healthDmg` сырое значение игры, может превышать остаток здоровья (для ADR режется по предыдущему hp жертвы) |
| `blinds` | `[tick, thrower, victim, durationMs]` |

### bomb (этап 5)

| Поле | Описание |
|---|---|
| `plantTick`, `x`, `y`, `z`, `planter` | Установка: тик, позиция (десятые) по снимку установщика, индекс игрока. `null`, если не ставили |
| `endTick`, `endType`, `defuser` | `endType`: `"exploded"` или `"defused"`; `defuser` индекс разминировавшего. `null`, если бомба не дожила до конца (раунд кончился раньше) |
| `carrier` | Кто держит бомбу до установки: пары `[i, игрок]`, игрок `-1` значит бомба лежит на земле. Запись на первом снимке и при каждой смене. Носитель это живой игрок с C4 в инвентаре |
| `trackX`, `trackY`, `trackZ` | Позиция бомбы на каждом снимке от начала раунда до установки (префикс `ticks`): позиция носителя или место, где её выронили |
| `drops`, `pickups` | События выброса и подбора: `[tick, игрок, x, y, z]` (позиция игрока по ближайшему снимку) |

### grenades (этап 6)

Список гранат, брошенных в раунде (раунд определяется по `throwTick`, как у событий), по возрастанию `throwTick`.

| Поле | Описание |
|---|---|
| `type` | `smoke`, `he`, `flash`, `fire`, `decoy`. Молотов и зажигательная гранаты не различаются: оба `fire`, рисуются одинаково |
| `thrower` | Индекс игрока |
| `throwTick` | Первый тик существования снаряда |
| `endTick` | Конец полёта: взрыв HE, вспышка флешки, раскрытие дыма, начало огня. Если события нет, последний тик, когда снаряд был виден |
| `ticks`, `x`, `y`, `z` | Траектория: точка на каждом тике от `throwTick` до `endTick` (последняя точка всегда ровно `endTick`). Поэтому излом после удара о стену или пол виден сам, достаточно соединить точки отрезками. Не совпадает по индексам с `Round::ticks` (там шаг 4) |
| `area` | Только у дыма и огня: `{startTick, endTick, x, y, z}`. `endTick` равен `null`, если эффект не закончился до конца раунда (демка не пишет события конца) |

Отдельных событий и точек отскока нет. В демках CS2 события отскока не существует, а излом траектории и так записан: шаг по тикам 1 вместо 4 (полёт короткий, 150 гранат дают около 20 тыс. точек, 0,5 МБ из 5 МБ).

Источники: полёт из покадровых позиций снарядов (отдельный проход по демке), конец полёта, области дыма и огня из событий `*_detonate`, `smokegrenade_expired`, `inferno_startburn`, `inferno_expire`.

### summary (этап 7a)

`rounds[].summary[p]` сводка игрока `p` за раунд: `{kills, deaths, assists, damage, headshots, flashAssists, kast}`. Считается из `events`, правила ниже.

## stats (этап 7a)

`stats.perPlayer[p]` итоги игрока `p` за матч (индекс = `players[].index`):

| Поле | Описание |
|---|---|
| `rounds` | Раунды, где у игрока была сторона (ушедший игрок не считает раунды после ухода) |
| `kills`, `deaths`, `assists` | Счёт. Убийство своего (`teamKills`) и самоубийство или смерть от мира убийством не считаются, но смерть считается |
| `damage` | Урон врагам. Урон по своим, себе и от мира не считается; режется по остатку здоровья жертвы (hp начинается со 100 в каждом раунде и берётся из `victim hp after` предыдущего удара) |
| `headshots`, `hsPercent` | Убийства в голову и их доля среди убийств, процент с одним знаком |
| `adr` | `damage / rounds`, один знак |
| `kastPercent` | Доля раундов, где был Kill, Assist, игрок выжил (нет смерти в раунде) или Trade (союзник убил убийцу не позже 5 секунд после смерти), один знак |
| `flashAssists` | Помощь флешкой: убийства с флагом 32, у ассистента (только по врагам) |
| `enemiesBlinded`, `enemyBlindMs` | Сколько раз и на сколько миллисекунд игрок ослепил врагов (свои и себя не считает) |

Статистика не зависит от названий оружия, поэтому сопоставление имён в `weapons` для неё не нужно.
