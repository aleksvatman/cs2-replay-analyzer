# Формат JSON (schemaVersion 1)

Контракт между `parser-core`, сервером и приложением. Источник истины в коде: `parser-core/src/models.rs`. Любое несовместимое изменение формата повышает `schemaVersion`.

Статус: реализованы верхний уровень, `players`, раунды и снимки игроков с экономикой (этапы 3-4). Остальное ниже помечено «план» и пока не в коде.

## Верхний уровень

| Поле | Тип | Описание |
|---|---|---|
| `schemaVersion` | число | Версия формата, сейчас 1 |
| `map` | строка | Название карты, например `de_mirage` |
| `tickRate` | число | Тиков в секунду. Демка частоту не отдаёт: считается как тики / `game_time` по первому раунду, при сбое 64 |
| `players` | список | Игроки матча |
| `weapons` | список строк | Словарь названий оружия и предметов: в данных только индексы (порядок первого появления) |
| `rounds` | список | Раунды по порядку |
| `stats` | объект | Статистика по игрокам (план, этап 7a) |

## players

`{ index, steamId, name, finalTeam }`. `index` используется везде как ссылка на игрока. `finalTeam` это `"T"`, `"CT"` или `null`: сторона в конце матча. Стороны меняются на полувремени, поэтому команда в конкретном раунде хранится в раунде (`teams`, план, этап 4).

## rounds

Сейчас:

| Поле | Описание |
|---|---|
| `number` | Номер с 1, овертайм продолжает счёт |
| `startTick` | Тик начала раунда (`round_start`; для первого раунда не раньше `begin_new_match`) |
| `freezeEndTick` | Конец заморозки (`round_freeze_end`), `null`, если раунд кончился раньше (сдача) |
| `endTick` | Тик `round_end` |
| `winner` | `"T"`, `"CT"` или `null` |
| `reason` | Код причины из игры: 1 взрыв бомбы, 7 разминирование, 8 убиты все T, 9 убиты все CT, 18 сдача CT. Неизвестные коды передаются как есть |

Раунды собираются так: всё до `begin_new_match` (разминка, рестарты) отбрасывается; раунд существует, только если у него есть начало и конец, оборванный в конце раунд не попадает в результат.

Снимки (этап 4). Все массивы игрока имеют длину `ticks`; индекс `i` везде значит снимок `i`.

| Поле | Описание |
|---|---|
| `ticks` | Тики снимков: `startTick`, +4, +8, ... до `endTick` (заморозка включена) |
| `teams` | Сторона каждого игрока в этом раунде (`"T"`, `"CT"`, `null`), индекс = `players[].index` |
| `tracks` | Данные игроков, индекс = `players[].index` |

`tracks[p]`:

| Поле | Описание |
|---|---|
| `x`, `y`, `z` | Позиция, целые десятые игровой единицы. У мёртвого сохраняется последняя известная позиция |
| `yaw`, `pitch` | Целые десятые градуса: yaw -1800..1800, pitch -900..900 |
| `hp` | 0..100, `0` значит мёртв |
| `weapon` | Смены активного оружия: пары `[i, id оружия]` (первая запись на первом снимке с живым игроком) |
| `money` | Деньги на каждом снимке |
| `inventory` | Смены инвентаря: `[i, броня, флаги, [id предметов]]`. Флаги: бит 0 шлем, бит 1 набор сапёра. Запись на первом снимке и при каждом изменении |
| `spent` | Потрачено за закупку: `cash_spent_this_round` на последнем снимке до конца заморозки |

Для мёртвого игрока `weapon` и `inventory` не обновляются (остаётся состояние перед смертью). Игрок, которого нет в данных тика, считается мёртвым.

План (этапы 5-7):

- `grenades`, `bomb` (включая трек брошенной бомбы и события выброса и подбора), `events` (убийства, урон, ослепления).

## stats (план)

По игроку за матч и по раундам: kills, deaths, assists, damage, процент хедшотов, ADR, KAST, flash assists.
